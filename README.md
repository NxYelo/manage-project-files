# manage-project-files

一个用于团队项目文件治理的 Codex Skill：统一建立项目文件树，解释每个目录的职责，判断文件应该放在哪里，巡检现有工作区，并在用户确认后安全执行整改。

它解决的不是“把文件随便分几个文件夹”，而是让团队对以下问题使用同一套答案：

- 一个新项目应该建立哪些目录？
- 客户需求、参考资料、工作稿、已定稿文件分别放在哪里？
- 哪个版本才是当前有效版本？
- 根目录散落的文件应该如何处理？
- 项目经验什么时候可以升级为团队知识？
- AI 生成的文件如何命名和识别？
- 如何巡检和整改，同时避免误移动、覆盖或删除文件？

## 主要能力

### 1. 建立标准工作区

生成工作区规则、巡检清单、项目总索引和整体归档目录，并可关联独立的团队知识库。

### 2. 建立标准项目文件树

根据 `YYYYMM 项目名` 创建完整项目结构、项目 README 和项目分类规则，并自动更新项目总索引。

### 3. 解释文件夹职责

说明每个文件夹：

- 用来存放什么；
- 不应该存放什么；
- 文件完成当前阶段后应该流向哪里。

### 4. 判断文件归属

根据文件的内容性质、约束力、成熟度和当前状态，判断其应进入需求、策划、参考、执行、知识、历史归档或临时目录。信息不足时不会猜测，而是建议先进入 `00_输入待分配`。

### 5. 只读巡检

检查缺失目录、项目命名、输入超期、根目录散放、历史版本标记、AI 文件后缀、README 映射和长期不活跃项目。巡检默认只报告，不修改文件。

### 6. 安全整改

先生成逐项整改计划，再由用户批准具体操作 ID。执行前重新校验源文件和目标路径；出现源文件变化、目标冲突或路径越界时停止，不覆盖文件，也不永久删除文件。

### 7. 整改后复检

整改完成后重新运行同一套规则，确认哪些问题已解决、哪些仍需人工判断。

## 标准文件树

```text
团队工作区/
├── 00_工作区文件管理规则.md
├── 00_巡检清单.md
├── 00_项目总索引.md
├── YYYYMM 项目名/
│   ├── 00_README.md
│   ├── 00_文件分类与归档规则.md
│   ├── 00_输入待分配/
│   ├── 01_需求输入/
│   ├── 02-项目策划/
│   ├── 03_参考资料/
│   ├── 04_项目执行资料/
│   ├── 05_知识沉淀/
│   ├── 98_历史归档/
│   ├── 99_未归档/          # 可选
│   └── temp/
└── 归档/
    └── YYYYMM 已结案项目/
```

注意：`02-项目策划` 使用短横线，不是下划线。

## 各目录的作用

| 目录 | 主要用途 | 后续流向 |
|---|---|---|
| `00_输入待分配` | 暂时无法判断归属的新材料 | 7天内分流到01、03、04、05或99 |
| `01_需求输入` | 客户需求、确认口径、事实输入和指定模板 | 形成决策后进入02或04 |
| `02-项目策划` | Brief、策略、计划、项目规则和成熟SOP | 跨项目验证后进入05 |
| `03_参考资料` | 原始资料、第三方报告、案例和研究 | 摘要或应用成果进入02或04 |
| `04_项目执行资料` | 方案、脚本、审核稿、看板和交付物 | 定稿升级02/05，旧稿进入98 |
| `05_知识沉淀` | 已验证并可跨项目复用的经验 | 成熟后提升至团队知识库 |
| `98_历史归档` | 旧版、重复件和被替代文件 | 只用于追溯 |
| `99_未归档` | 非业务杂物或暂不治理内容 | 定期复核或清理 |
| `temp` | 可再生成的缓存、锁文件和中间产物 | 可定期清理 |

## 如何调用

Skill 支持自然语言自动触发，也可以显式指定：

```text
$manage-project-files 建立一个新的团队工作区
$manage-project-files 新建“202609 某项目”并生成完整目录树
$manage-project-files 这个文件应该放在哪个文件夹？
$manage-project-files 巡检整个工作区，先不要修改
$manage-project-files 给出整改方案，先不要移动文件
$manage-project-files 执行刚才确认的整改计划
```

详细输入要求、缺少材料时的处理方式和执行命令见 [`SKILL.md`](SKILL.md)。

## 工作方式

```text
读取规则和配置
      ↓
识别工作区与项目
      ↓
只读巡检或判断归属
      ↓
展示预览和整改计划
      ↓
用户批准具体操作
      ↓
校验源文件、目标和边界
      ↓
执行批准项并复检
```

没有用户确认时，Skill 停留在预览、报告或计划阶段。

## 安装

将完整仓库克隆到 Codex Skills 目录：

```powershell
git clone https://github.com/NxYelo/manage-project-files.git "$env:USERPROFILE\.codex\skills\manage-project-files"
```

如果仓库为 Private，需要先完成 GitHub 登录授权。安装后新建一个 Codex 任务，Skill 即可被发现。

更新 Skill：

```powershell
Set-Location "$env:USERPROFILE\.codex\skills\manage-project-files"
git pull
```

## 配置

默认政策位于 [`references/default-policy.json`](references/default-policy.json)。团队专属路径、AI 映射、技术目录白名单和项目例外应放在 Skill 外部配置中，避免把客户资料或本机信息提交到公共仓库。

配置示例和合并规则见 [`references/configuration.md`](references/configuration.md)。完整治理规则见 [`references/governance.md`](references/governance.md)。

## 安全原则

- 默认先预览，再执行。
- 巡检只读，不自动整改。
- 含糊文件不自动分类。
- 只执行用户批准的操作 ID。
- 不覆盖已有目标文件。
- 源文件在计划后变化时停止。
- 所有路径必须位于目标工作区内。
- 不永久删除文件。
- 客户资料、账号凭据和真实项目配置不进入 Skill 包。
